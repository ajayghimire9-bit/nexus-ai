# Proposed next experiment: frozen terminal-value calibration

Status: proposal only, not executed and not covered by the consumed terminal-value budget. No new controller or architecture is proposed.

Question: does the fitted readout generalize to new states, and how much does endpoint prediction change its value error? The completed first-action pilot was inconclusive (−0.221 [−5.881,+5.438]) despite changing51.3% of student actions and fitting source labels better than a constant. Its query returns are not labels for full16-action prefixes, so held-out value accuracy remains unmeasured.

Freeze all ten current readouts, original decoders/student encoders and normalization. Reuse the exact recorded context vectors from the completed source/evaluation input rows; this deliberately isolates new-state calibration from support-history variation and requires **no new support collection**. Verify vector fingerprints and readout hashes. Do not refit or select a new ridge value.

On the same eight source and three development physics, preregister one fresh reset and one shared16×16 candidate array per task, disjoint from every closed episode/RNG seed. Use four fixed candidate indices [0,4,8,12], as in source fitting. Execute each full16-action prefix once, then48 steps of the corresponding decoder's unchanged zero MPC. Score the same target return using V(model-predicted endpoint,z), V(actual endpoint,z), and the fixed source-label mean. Actual simulator state is a research-only input; it must not enter a deployed controller. Actual-endpoint inputs can themselves be out of the fitted distribution, so they are not an oracle.

Primary proposal: student-context, imagined-endpoint RMSE versus fixed source-mean RMSE on the held-out development states, averaging five students/tasks within each decoder. Prespecify at least10% mean reduction and a positive paired95% decoder-level benefit as a development screen. Source-state calibration and actual-versus-imagined endpoint error are secondary, with unadjusted intervals. All ten decoders remain; candidates/student seeds/tasks are not extra model-training replications. Poor calibration with both inputs would support a readout/coverage problem; a gap between inputs would motivate endpoint analysis, without establishing causal full-control failure. A null remains acceptable.
